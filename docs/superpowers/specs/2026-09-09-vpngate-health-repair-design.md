# VPNGate 现网健康修复设计

## 目标

修复云途快照同步死锁、节点硬门槛有效期与每日维护错配、管理 UI 公网暴露和日志无运行期轮转四个现网问题，同时保留现有池、凭据、代理入口和 fail-closed 行为。

## 设计

1. `apply_snapshot_file()` 仍完整校验传入快照；读取现有快照时只解析受限大小的 JSON，并校验 `schema_version` 与正整数 `sequence`。现有文件的时间过期不阻止更新，但损坏、未知 schema 或序号回退仍拒绝。
2. `HARD_GATE_TTL_SECONDS` 从 7200 调整为 108000（30 小时）。每日 03:00–04:00 的维护仍负责重新验证，额外 6 小时覆盖维护耗时和调度抖动；不增加探测频率。
3. 新安装默认 `UI_HOST=127.0.0.1`。升级时安装器只把历史通配绑定 `::`/`0.0.0.0` 迁移为回环，保留端口、路径和登录凭据；显式的其他绑定不擅自改写。
4. 使用系统原生 `logrotate` 管理 `vpngate.log`：10 MiB 轮转、保留 7 份、压缩、`copytruncate`，无需重启常驻进程。安装器部署配置，正式验收检查配置存在。

## 验收

- 过期 schema v2 当前快照可被更高序号的新鲜快照覆盖，旧文件仍进入 previous；序号回退及损坏文件仍拒绝。
- 两个正式 profile 和验收脚本统一使用 108000 秒。
- 东京升级后 8787 仅监听回环，网页登录经 SSH 转发仍正常。
- 三台存在 `/etc/logrotate.d/aimilivpn`，强制轮转测试成功。
- 云途同步服务恢复成功，当前快照序号前进且 failed unit 清零。

## 非目标

- 不拆分 `vpngate_manager.py`。
- 不修改 3x-ui、nginx、Cloudflare、VLESS、Trojan、HY2 或订阅管线。
- 不重写 Git 历史。
