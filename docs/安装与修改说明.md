# VPNGate 项目：安装与修改说明

本文说明本项目解决了什么、如何安装到新 VPS，以及它与 3x-ui/CDN 订阅的边界。公开发布前请把仓库、服务器和联系方式占位符替换为部署环境值。

## 1. 版本定位

这不是新的代理协议。AimiliVPN 负责在 VPS 本机连接 VPNGate，并提供本地 HTTP/SOCKS5 代理；客户端仍使用原来的 VLESS、CDN 或其他协议接入 VPS。

```text
仅 AimiliVPN：VPS 本机程序 -> 127.0.0.1:7928 -> VPNGate -> 日本住宅出口

与 3x-ui 集成：客户端 -> 原 VLESS/CDN 入站 -> Xray 路由 -> AimiliVPN -> 日本住宅出口
```

正式安装器默认只安装 AimiliVPN，不会修改 3x-ui、nginx、Cloudflare、CDN 优选源或现有订阅。需要“CDN 入口、VPNGate 出口”时必须另做 3x-ui 路由接入，并保留原直连 CDN 订阅。

## 2. 安装前要求

- 推荐 Debian 12 或 Ubuntu，至少 1 GB 内存。
- 使用 root，或具备完整 sudo 权限。
- VPS 必须提供 `/dev/net/tun` 字符设备；LXC/OpenVZ 需先在商家面板启用 TUN/TAP。
- 能访问 VPNGate、GitHub（GitHub 仅下载时需要）及 IP 检测服务。
- 默认管理端口为 `8787`；本地代理 `7928` 只监听 `127.0.0.1`，不应向公网开放。
- 每台 VPS 单独建立节点池，不复制其他 VPS 的可信池，因为实际可达性、速度和出口会受源线路影响。

安装前可执行：

```bash
cat /etc/os-release
test -c /dev/net/tun && echo "TUN OK"
free -m
df -h / /opt
ss -lntup
```

## 3. 从本地部署包安装

本地部署包和同名 `.sha256` 文件保存在：

```text
<LOCAL_RELEASE_DIRECTORY>/
```

先在 Mac 验证并上传：

```bash
cd "<LOCAL_RELEASE_DIRECTORY>"
shasum -a 256 -c <部署包名>.tar.gz.sha256
scp <部署包名>.tar.gz <部署包名>.tar.gz.sha256 root@<VPS-IP>:/tmp/
```

然后登录 VPS：

```bash
cd /tmp
sha256sum -c <部署包名>.tar.gz.sha256
tar -xzf <部署包名>.tar.gz
cd <解压目录>
bash install-local-package.sh
```

安装器会：

1. 检查 root、TUN、系统类型和基础依赖。
2. 拒绝覆盖来源不明的 `/opt/aimilivpn`。
3. 把正式代码部署到 `/opt/aimilivpn`。
4. 备份原 `/etc/default/aimilivpn`，再写入正式住宅策略。
5. 保留已有 `vpngate_data`、节点池和管理账号。
6. 配置并启动 `aimilivpn` 服务。
7. 运行 `scripts/verify-formal-install.sh`。
8. 输出管理地址、账号和密码。

## 4. 从 GitHub 仓库取得部署包

仓库地址：`<PUBLIC_REPOSITORY_URL>`

在已登录 GitHub CLI 的 Mac 上下载最新 Release：

```bash
gh release list --repo OWNER/REPOSITORY
gh release download <版本标签> --repo OWNER/REPOSITORY --dir /tmp/project-release
cd /tmp/project-release
shasum -a 256 -c *.tar.gz.sha256
```

验证后再按上一节上传到 VPS。仓库保存源码，Release 可保存可直接部署的 `.tar.gz` 和 `.sha256`。

## 5. 升级与回滚原则

升级使用新部署包重复执行 `bash install-local-package.sh`。安装器只允许覆盖：

- 本项目的 Git 仓库；或
- 带 `.aimilivpn-managed` 标记的正式安装。

它不会主动删除节点池。环境配置升级前会生成带时间戳的备份：

```text
/etc/default/aimilivpn.backup.YYYYMMDD-HHMMSS
```

升级后先运行：

```bash
bash /opt/aimilivpn/scripts/verify-formal-install.sh
systemctl status aimilivpn --no-pager
journalctl -u aimilivpn -n 100 --no-pager
```

不要在未确认备份和目录来源的情况下删除 `/opt/aimilivpn`、`vpngate_data` 或系统服务。

## 6. 相比原项目的主要修改

### 6.1 检测真实出口，不把 VPNGate 服务器 IP 当落地 IP

候选节点会用独立测试网卡（如 `tun2+`）建立 OpenVPN 隧道，并通过该隧道查询实际公网出口。测试不会切走当前正常使用的 `tun0`，因此后台筛选其他节点时，当前连接可以继续工作。

系统同时记录：

- 实际出口 IP；
- 国家和住宅类型；
- 风险标记；
- 下载速度、首包时间和隧道延迟；
- IP 质量、稳定性、网络和综合评分。

### 6.2 多来源 IP 判断

当前综合使用：

- `ipapi.is`
- `ip.net.coffee`
- `cleanip.io`
- `ip-api.com`（运营商、位置和初步类型补充）

新节点必须确认实际出口为日本、住宅且没有明确风险，才会进入可用池。IP 质量分采用可用评分源的中位数，不把任一网站的单一结论当绝对真相。

所有信誉服务都不可用时，新节点不会被宽松放行；当前出口与缓存一致时可以复用已保存的检测结果，避免单个检测网站临时故障立即切断一个已经验证过的稳定节点。

### 6.3 可信池和观察池

- 可信池最多 10 个：IP 质量至少 90，且至少连续成功 2 次。
- 观察池最多 10 个：通过硬性日本住宅检查，但尚未达到可信条件。
- 可信池和观察池都满后，其余合格节点进入冷却状态，避免检测任务无限增长。
- 连续 7 个不同日期检测失败的节点进入休眠状态；资料和 OpenVPN 配置保留，可供以后低频复查。
- 日常连接先按可信池综合评分排序，再使用观察池；没有合格节点时严格关闭。

### 6.4 收藏与自动池分离

网页“我的收藏”用于人工保存和切换，不是自动可信池：

- 人工收藏或取消收藏不改变可信池排序。
- 人工可以切换任意节点。
- 评分 100 且无风险的可信节点可以自动加入收藏。
- 用户手动取消自动收藏后会记录退出意愿，不会立即再次自动收藏。
- 自动维护仍可在发现明显更优节点时择优切换，但一天最多执行一次优化切换。

### 6.5 定时维护和紧急补池

- 正常综合维护：每天系统时间 `03:00–04:00`。
- 备用检测结果有效期：26 小时。
- 每批测试 10 个，单轮最多 20 个，并发最多 2 个。
- 备用池不足时允许紧急补池，但两次紧急补池至少间隔 6 小时。
- 当前节点评分已经达到 100 时，不为追求无意义的小幅提升主动切换。

### 6.6 严格失败关闭

本地代理套接字使用 `SO_BINDTODEVICE` 绑定 `tun0`。如果没有合格住宅节点、TUN 消失或连接验证失败：

- 停止活动 OpenVPN；
- 清理活动节点状态；
- 本地代理报错；
- 不允许流量回退到 VPS 默认公网出口。

这会牺牲“始终能联网”，换取“不泄漏 VPS 原生出口”。

### 6.7 文件与资源控制

- 可信、观察、冷却、休眠、活动或收藏节点的配置持久保存。
- 配置按内容哈希去重，内容不变时不重复写文件。
- 临时测试配置在任务结束后清理。
- 日志和测试残留定期清理，避免大量临时文件影响 VPS。

## 7. 正式环境参数

正式模板位于 `/etc/default/aimilivpn`：

| 参数 | 值 | 含义 |
| --- | ---: | --- |
| `STRICT_RESIDENTIAL_ONLY` | `true` | 只允许住宅出口 |
| `TRUSTED_POOL_LIMIT` | `10` | 可信池上限 |
| `OBSERVATION_POOL_LIMIT` | `10` | 观察池上限 |
| `TRUST_MIN_IP_SCORE` | `90` | 可信池最低 IP 质量分 |
| `TRUST_MIN_SUCCESSES` | `2` | 可信池最低连续成功次数 |
| `AUTO_FAVORITE_SCORE` | `100` | 自动收藏分数 |
| `STANDBY_TARGET` | `10` | 备用目标数 |
| `STANDBY_MAX_AGE_SECONDS` | `691200` | 检测有效期 8 天 |
| `STANDBY_SCAN_BATCH_SIZE` | `10` | 每批测试数 |
| `STANDBY_SCAN_LIMIT` | `20` | 单轮测试上限 |
| `TEST_MAX_WORKERS` | `2` | 测试并发上限 |
| `DAILY_MAINTENANCE_START_HOUR` | `3` | 日常维护开始时间 |
| `DAILY_MAINTENANCE_END_HOUR` | `4` | 日常维护结束时间 |
| `STABLE_POOL_PROBE_DAILY_LIMIT` | `2` | 稳定池每日轮换短测节点上限 |
| `STABLE_POOL_PROBE_BYTES` | `1000000` | 稳定池短测下载上限（1 MB） |
| `FULL_PROBE_BYTES` | `5000000` | 新节点、补池与手动完整测试下载上限（5 MB） |
| `EMERGENCY_REFILL_COOLDOWN_SECONDS` | `21600` | 紧急补池冷却 6 小时 |
| `LOCAL_PROXY_HOST` | `127.0.0.1` | 代理仅限 VPS 本机 |
| `LOCAL_PROXY_PORT` | `7928` | 本地 HTTP/SOCKS5 端口 |
| `UI_PORT` | `8787` | 网页管理端口 |

## 8. 安装后验收

最低验收：

```bash
bash /opt/aimilivpn/scripts/verify-formal-install.sh
systemctl is-enabled aimilivpn
systemctl is-active aimilivpn
ss -lntp
```

业务验收还必须确认：

1. 管理网页可以打开并登录。
2. 实际出口是日本住宅且无明确风险，不只是 VPNGate 列表中的服务器地址。
3. 可信池和观察池均不超过 10。
4. 代理只监听回环地址。
5. 模拟没有合格节点时不会走 VPS 默认出口。
6. 如果接入 3x-ui/CDN，原直连 CDN 订阅仍可用，新增订阅出口才经过 VPNGate。

## 10. 已知边界

- VPNGate 是志愿节点网络，住宅 IP 可能下线或更换，系统只能通过池化和自动切换降低中断概率，不能保证某个公网 IP 永久存在。
- IP 分类网站可能有误判，因此采用多来源、缓存和连续成功，不把“100 分”解释为永久可信。
- VPNGate 落地的速度由 VPS 到志愿节点线路、节点上行、负载、加密开销和客户端入口共同决定；IP 干净不等于速度快。
- 本项目不自动创建 Cloudflare/CDN 订阅，也不应绕过 3x-ui 原生入站和订阅导出流程。
